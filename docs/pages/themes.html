Themes & View Overrides

Override only the Blade files you need. Keep your copies in the application, not in Composer's vendor directory.

Override the active theme

For the bundled default theme, copy the view from the package to the matching application path:

From: vendor/webregulate/laravel-administration/src/resources/views/themes/default/auth/login.blade.php
To:   resources/views/vendor/wrla/themes/default/auth/login.blade.php

WRLA checks the application's selected theme first, then the package's selected theme, then the unthemed package view. For another theme, replace default with its configured path. Non-themed overrides requested by WRLA's view resolver go directly under resources/views/vendor/wrla/.

Start with the existing template to preserve routes, form fields, and Livewire bindings. After an upgrade, compare your override with the shipped version. For colors and CSS without copying markup, see Configuration.

Use theme-aware Blade directives

@themeView renders a named view. @themeComponent looks under components and takes a data array. These are view paths, not Blade component class names.

@themeView('layouts.partials.partial-left-panel')

@themeComponent('heading', ['title' => 'Reports', 'icon' => 'fa-solid fa-chart-bar'])

Use the directives in templates rendered inside WRLA. Use normal Blade includes or components if your view should not depend on the active WRLA theme. After changing overrides, clear compiled views with php artisan view:clear.
