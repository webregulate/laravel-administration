Advanced Manageable Models

Edit related records, react to form changes, transform submitted values, and add calculated columns without replacing WRLA's form or table.

Edit a related record

Use relationship.attribute to edit a field on a single related model. This example assumes the Eloquent Product model has a hasOne relationship named details, backed by a table that stores product_id and subtitle.

use WebRegulate\LaravelAdministration\Classes\ManageableFields\Text;

// In getManageableFields()
Text::make($this, 'details.subtitle')->validation('nullable|string|max:120'),

This edits the related record itself. To choose a different existing related record, use a SearchSelect bound to the foreign key instead. For custom work before WRLA writes a related field, see save hooks.

Show a field when another value changes

Bind the controlling field with setLivewireModel('live'). Read its current value when building the field list. These attributes must exist on your Eloquent model.

use WebRegulate\LaravelAdministration\Classes\ManageableFields\Select;
use WebRegulate\LaravelAdministration\Classes\ManageableFields\Text;

public function getManageableFields(): array
{
    $type = static::getLivewireField('type') ?? $this->model()->type ?? 'physical';

    return [
        Select::make($this, 'type', ['physical' => 'Physical', 'digital' => 'Digital'])
            ->setLivewireModel('live')
            ->validation('required|in:physical,digital'),
        ...($type === 'digital' ? [
            Text::make($this, 'download_url')->validation('required|url'),
        ] : []),
    ];
}

Hiding a field does not clear its stored value. Add an explicit save rule if changing the type should clear the old URL.

Transform a submitted value

use Illuminate\Http\Request;
use WebRegulate\LaravelAdministration\Classes\ManageableFields\Text;

// In getManageableFields()
Text::make($this, 'sku')
    ->validation('required|string|max:32')
    ->appendApplySubmittedValue(
        fn (Request $request, mixed $value) => strtoupper(trim($value)),
    ),

The callback runs after form validation. appendApplySubmittedValue() keeps earlier callbacks, while overrideApplySubmittedValue() replaces the callback chain. If other write paths must normalize a value too, put the rule on the Eloquent model instead.

Add a query-backed browse column

Use a query modifier when the database should calculate the value before pagination. In this example, reviews() is an Eloquent relationship on Product.

use Illuminate\Database\Eloquent\Builder;
use WebRegulate\LaravelAdministration\Classes\BrowseColumns\BrowseColumn;

public function getBrowseColumns(): array
{
    return [
        'name' => 'Product',
        'reviews_count' => BrowseColumn::query(
            'Reviews',
            static::class,
            fn (Builder $query) => $query->withCount('reviews'),
        ),
    ];
}

The array key must match the selected alias. Use BrowseColumn::selectRaw() for a fixed SQL expression; never interpolate user input into raw SQL. For a display-only change, use BrowseColumn::make() with a formatter instead.
