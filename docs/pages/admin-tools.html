Admin Tools

WRLA includes tools for files, logs, database inspection, and jobs. Set access rules in WRLASettings::runtime() and tool options in config/wrla.php.

Choose who can use each tool

Developer Tools, File Manager, and Logs are master-only in the generated settings. Database Browser, Database Schema, and Scheduler inherit Developer Tools access when their enabled value is null.

// Inside WRLASettings::runtime()
'scheduler' => [
    'enabled' => fn ($userData) => $userData?->isMaster() ?? false,
    'can_run_adhoc' => false,
],

This lets masters view scheduled tasks and jobs without manually running scheduled tasks. Pending jobs are shown only for a database queue. Failed jobs require a database failed-job store.

Make the database browser read-only

The browser shows raw records, not Manageable Models. Model permissions are not a substitute for restricting access here. Edit the existing database_browser settings:

// Inside config/wrla.php, under 'database_browser'
'connections' => ['reporting'],
'excluded_tables' => ['*' => ['users', 'sessions']],
'read_only' => true,

Use a connection defined in config/database.php. Database Schema is a separate tool with its own connection options and access rule.

Files, logs, and schema

  • File Manager: browse configured Laravel disks. Limit exposed disks and accepted upload MIME types under file_manager.
  • Logs: select WRLA's built-in viewer or Opcodes Log Viewer with logs.current.
  • Database Schema: inspect a Truss diagram. Use database_schema_viewer.display to embed it in WRLA or open the standalone viewer.

See Configuration for more options or Authorization for the admin and master flags.
