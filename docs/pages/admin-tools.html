Admin Tools

WRLA includes tools for files, logs, database inspection, and jobs. Set access rules in WRLASettings::runtime() and tool options in config/wrla.php.

Choose who can use each tool

Use a boolean or a callback that receives the current user's WRLA user data. The generated settings use these rules:

Developer Tools

The modal links to the database tools when available. It can also run a configured list of maintenance commands and show their output. Add entries under developer.commands in WRLASettings::runtime():

[
    'command' => 'php artisan view:clear',
    'label' => 'Clear compiled views',
    'condition' => fn ($userData) => $userData?->isMaster() ?? false,
    'refresh' => false,
],

condition limits the individual command. Set 'refresh' => true to offer a reload after an update command finishes. Keep this list limited to operations trusted admins should be able to run.

Scheduler & Jobs

SectionWhat you can doRequirement
Scheduled tasksSee the schedule, time zone, and next run. Run a task now if allowed.Tasks registered with Laravel's scheduler
Pending jobsInspect or delete a pending job.The default queue connection uses the database driver
Failed jobsRetry or forget one job, retry all jobs, or clear all failures.A database-backed failed-job store

To let masters use the page without manually running scheduled tasks:

// Inside WRLASettings::runtime()
'scheduler' => [
    'enabled' => fn ($userData) => $userData?->isMaster() ?? false,
    'can_run_adhoc' => false,
],

can_run_adhoc defaults to null, which inherits Scheduler access. Turning it off does not make the page read-only: queue actions remain available. WRLA does not replace your scheduler or queue worker.

Database Browser

Browse tables, sort and filter rows, and open full record values. Where allowed, create, edit, or delete raw records. This does not use Manageable Model forms or permissions.

For a read-only reporting connection, edit the existing settings:

// Inside config/wrla.php, under 'database_browser'
'connections' => ['reporting'],
'excluded_tables' => ['*' => ['users', 'sessions']],
'read_only' => true,
  • connections selects Laravel connection names; null allows all and [] allows none. excluded_tables supports wildcard patterns and per-connection exclusions.
  • read_only_connections disables writes on selected connections. For writable connections, set separate create, edit, and delete rules under database_browser.permissions in runtime settings.
  • Tune filters, page sizes, previews, and modal or page forms under database_browser in config/wrla.php.

Database Schema

Use the Truss diagram to inspect schema and relationships. This is separate from the Database Browser. Its access rule and connections are configured independently.

// Inside config/wrla.php, under 'database_schema_viewer'
'display' => 'embed', // Or 'redirect' for the standalone viewer.
'default_mode' => 'dark',
'connections' => ['reporting' => ['excluded_tables' => ['legacy_import']]],

An empty connection list uses Laravel's default. Pass additional Truss options through the truss key.

File Manager

Browse and preview files, upload or replace them, and create or delete folders. Enable only storage disks intended for admin access; an initial disk selection does not restrict which disks users can switch to.

// Inside config/wrla.php, under 'file_manager'
'default_filesystem' => 'public',
'file_systems' => ['public' => ['enabled' => true]],
'can_upload_mime_types' => ['image/jpeg', 'image/png'],

Logs

The built-in viewer browses, displays, and deletes log files. To use it instead of Opcodes:

// Inside config/wrla.php, under 'logs'
'current' => 'wrla',
'wrla' => ['max_characters' => 1000000],

With current set to opcodesio/log-viewer, set display_within_wrla in that viewer's WRLA settings to embed it instead of redirecting. Configure Opcodes itself in config/log-viewer.php. WRLA's error, info, and event log channels are configured separately under logging.
