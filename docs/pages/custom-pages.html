Custom Pages

Add your own full-page screens to the admin panel by writing a standard Livewire v3 component that extends WRLAPageComponent. It renders inside the WRLA admin layout automatically — sidebar, header, and theme included.

What is it?

WRLAPageComponent is a thin base class that extends Livewire\Component. Extend it instead of Livewire\Component and your component's view is wrapped in the WRLA admin layout on full-page loads — no @extends or layout boilerplate in your Blade file. This is the same mechanism WRLA's own internal pages (browse, create/edit, file manager, logs) are built on.

Why not #[Layout]? The WRLA layout path is theme-dynamic, so a literal #[Layout('...')] attribute can't be used. The base class applies the correct theme layout through a rendering() lifecycle hook instead.

1 Create the component

Create a Livewire component anywhere in your app (for example app/Livewire/WRLA/) and extend WRLAPageComponent. Its render() returns a normal Blade view just like any Livewire component. 

<?php

namespace App\Livewire\WRLA;

use Livewire\Attributes\Title;
use WebRegulate\LaravelAdministration\Livewire\WRLAPageComponent;

#[Title('My Page')]
class MyPage extends WRLAPageComponent
{
    public function render()
    {
        return view('livewire.wrla.my-page');
    }
}

2 Create the view

Your Blade file only contains the page's own content — no layout wrapper. WRLA injects it into the admin layout's content section automatically. 

{{-- resources/views/livewire/wrla/my-page.blade.php --}}
<div>
    <h1 class="text-2xl font-semibold">My Page</h1>
    <p>Hello from a custom WRLA page.</p>
</div>
As with all Livewire components, the view must have a single root element.

3 Register a route

Register the component against a route in your WRLASettings::buildRoutes() method (app/WRLA/WRLASettings.php). Routes defined here are already wrapped in a group that applies the admin base_url prefix and the wrla_is_admin middleware, so you don't need to add them yourself. It is recommended to prefix custom route names with wrla.. 

use Illuminate\Support\Facades\Route;
use App\Livewire\WRLA\MyPage;

public static function buildRoutes(): void
{
    Route::get('my-page', MyPage::class)
        ->name('wrla.my-page');
}

The page is now reachable at /{base_url}/my-page (for example /wr-admin/my-page), and only accessible to admin users.

Page titles

There are two ways to set the browser/page title:

  • Static — add the standard Livewire #[Title('My Page')] attribute to the class (shown above).
  • Dynamic — override protected function getPageTitle(): ?string and return the title at runtime. Returning null falls back to the #[Title] attribute (or leaves the title unset). 
use WebRegulate\LaravelAdministration\Livewire\WRLAPageComponent;

class MyPage extends WRLAPageComponent
{
    public ?string $recordName = null;

    protected function getPageTitle(): ?string
    {
        return $this->recordName
            ? "Editing {$this->recordName}"
            : 'My Page';
    }

    // ...
}

Add it to the navigation

To surface your page in the admin sidebar, register a navigation item in WRLASettings::buildNavigation() pointing at your route name. 

use WebRegulate\LaravelAdministration\Classes\NavigationItems\NavigationItem;

public static function buildNavigation(): array
{
    return [
        // ...existing items...

        NavigationItem::make(url: route('wrla.my-page'), name: 'My Page', icon: 'fa fa-file'),
    ];
}

Overriding the built-in pages

WRLA's built-in pages — the Dashboard, FileManager and Logs — are all just full-page components wired up in buildRoutes(). Fresh installs ship them there so they're visible and easy to change. To replace one, point its route at your own component; to disable one, remove its route. 

use Illuminate\Support\Facades\Route;
use WebRegulate\LaravelAdministration\Livewire\Dashboard;
use WebRegulate\LaravelAdministration\Livewire\FileManager;
use WebRegulate\LaravelAdministration\Livewire\Logs;
use App\Livewire\WRLA\CustomDashboard;

public static function buildRoutes(): void
{
    // Defaults — the built-in WRLA pages:
    Route::get('dashboard', Dashboard::class)->name('wrla.dashboard');
    Route::get('file-manager', FileManager::class)->name('wrla.file-manager');
    Route::get('logs', Logs::class)->name('wrla.logs');

    // Swap any of them for your own full-page component instead:
    // Route::get('dashboard', CustomDashboard::class)
    //     ->name('wrla.dashboard');
}

Build CustomDashboard like any other custom page (extend WRLAPageComponent). To keep the notifications widget from the default dashboard, include it in your view: 

@livewire('wrla.notifications-widget', [
    'userIds' => config('wr-laravel-administration.dashboard.notifications.user_groups'),
])
The dashboard has a safety net — if no wrla.dashboard route is defined, WRLA falls back to its built-in one. File manager and logs are only available when their routes are present.
