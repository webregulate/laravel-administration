Releasing a Version

Versioning is driven entirely by public git tags (published to Packagist). There is no versions.json to maintain — the version bar, update modal and this documentation all read the tags directly.

1 Merge your changes into main

Get all of the changes for this release onto the main branch as you normally would.

2 Add the release notes page

Copy an existing release page and rename it to the new version, eg. docs/pages/versions/v0.7.1.html, then fill in the breaking changes, features and fixes. It links into the Version History automatically.

3 Tag and push 

git tag 0.7.1
git push origin main --tags

4 Let Packagist pick it up

Packagist detects the new tag automatically via its GitHub webhook, usually within a minute. Consuming apps whose constraint allows it (eg. ^0.7.0) then see the update in the WRLA version bar and can apply it with Update WRLA or php artisan wrla:update.

Follow SemVer: patch (0.7.0 → 0.7.1) for fixes, minor (0.7 → 0.8) for features, major for breaking changes.
