Adds a developer-only Database Browser with schema-driven record management, alongside shared dynamic filter fixes and layout improvements.

Breaking Changes

  • None.

New Features

  • Added a Database Browser to Developer Tools, available only when WRLAHelper::userIsDev() is true. Access is checked on every Livewire request.
  • Browse reachable configured connections, search table names, and view records with sortable columns, configurable pagination, and dynamic filters. Unavailable connections are reported without blocking the browser; MySQL and MariaDB table lists are scoped to the configured database.
  • Added an opt-in all-column filter, enabled by default in the Database Browser. Positive searches match any column; negative searches require every column to pass. Commas combine terms with AND, and pipes combine alternatives with OR, including terms across different columns.
  • Added ManageableModelDynamic to infer browse columns, form fields, and schema-based validation from the selected table, including numeric, date, boolean, enum, and JSON fields.
  • Tables with a single-column primary key support viewing, creating, editing, and confirmed permanent deletion, including string keys. Tables without a primary key or with a composite primary key remain browse-only.
  • Record forms provide separate NULL and database-default controls, with generated, auto-increment, and binary fields read-only. Existing primary keys cannot be edited.
  • Record actions follow upsert.mode, using the configured modal size and close-after-save setting, loading feedback, and automatic table refresh after saving. Full-page routes remain available, including record links opened in a new tab.

Database Browser operations write directly to the database: they bypass application model hooks, soft deletes, and business validation. Schema-based validation and database constraints still apply, and deletions are permanent.

Changes & Improvements

  • Shared dynamic browse filters now accept supplied schema columns and initial filters, with optional all-column filtering disabled by default for existing manageable models.
  • Filter additions and removals now immediately update browse results, and numeric zero is no longer skipped as an empty filter value.
  • Numeric comparison filters now use the connection's query grammar to quote column names instead of hard-coded MySQL quoting.
  • Improved filter accessibility with unique input IDs, accessible labels, and remove-button tooltips, plus wrapping layouts for narrower screens.
  • Reduced admin content padding to give wide tables more usable space.
  • Added focused Database Browser regression coverage using disposable in-memory SQLite databases.
