Introduces a unified alert notification system for Livewire actions and standard requests, alongside improvements to modal upserts, instance actions, and navigation items.

Breaking Changes

  • None. Existing published configuration remains valid, but the new alerts block below should be added.

Features

  • New alert popouts provide consistent success, danger, warning, and info notifications across admin and authentication pages.
  • Alerts support configurable expiry, a maximum visible count, optional links, manual dismissal, and session-storage persistence while navigating between pages.
  • Use WRLAHelper::pushAlert($type, $message, $url, $ttl) to send an alert from either a Livewire action or a standard request/redirect flow.
  • Manageable-model instance and multi-instance actions may now return an alert array containing message, type, url, and ttl. Existing string results remain supported as info alerts.
  • Navigation items now accept additional HTML attributes through setAttributes(), including modal-aware create links.

Improvements

  • Successful modal saves and deletes now refresh the underlying browse table automatically.
  • Deleting from an upsert form now closes modal forms correctly and preserves full-page navigation behaviour.
  • Create and edit forms now have contextual titles through ManageableModel::getUpsertTitle(), which can be overridden per model.
  • Modal actions use a dedicated footer slot, with improved form spacing and action alignment.
  • The package default for full-page upserts now returns to browse after a successful save. Existing published upsert.page.return_to_browse_after_save values continue to take precedence.
  • Authentication, MFA, file manager, browse, and upsert feedback now use the shared alert system.

Required Configuration

Add the following block to the general configuration section of your published config/wr-laravel-administration.php file: 

// Alert/notification popouts
'alerts' => [
    // TTL measured in milliseconds; use 0 to keep alerts open
    'ttl' => 5000,
    'max_visible' => 5,
    'top_offset' => '32px',
],

Bug Fixes

  • Browse views no longer remain stale after records are saved or deleted from an upsert modal.
  • Delete actions no longer attempt full-page redirects while running inside a modal.
