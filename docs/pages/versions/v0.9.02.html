Version History

Breaking Changes

  • The default browse filters are now provided by dedicated factory classes instead of ManageableModel helper methods. The following methods have been removed: getDefaultBrowseFilters(), getBrowseFilterSearch() and getBrowseFilterSoftDeleted().
  • Replace them with BrowseFilterSearch::make(static::class) and BrowseFilterSoftDeleted::make(static::class) from the new WebRegulate\LaravelAdministration\Classes\BrowseFilters namespace — mirroring the existing BrowseActions pattern.

Before

public final static function browseSetup(): void
{
    // Browse filters
    static::setBrowseFilters(static::getDefaultBrowseFilters());

    // ...or, expanded:
    static::setBrowseFilters(
        static::getBrowseFilterSearch(),
        static::getBrowseFilterSoftDeleted(),
        // ...other custom filters
    );
}

After

use WebRegulate\LaravelAdministration\Classes\BrowseFilters\BrowseFilterSearch;
use WebRegulate\LaravelAdministration\Classes\BrowseFilters\BrowseFilterSoftDeleted;

public final static function browseSetup(): void
{
    // Browse filters
    static::setBrowseFilters(
        BrowseFilterSearch::make(static::class),
        BrowseFilterSoftDeleted::make(static::class),
    );
}
Both factories accept optional arguments (alias, label, icon) that default to the previous values, so no configuration is required for a like-for-like migration. BrowseFilterSoftDeleted::make() still returns null for models without soft deletes and is safe to always include.

Features

  • New BrowseFilters namespace with BrowseFilterSearch, BrowseFilterSoftDeleted and a shared BrowseFilterBase, giving browse filters the same clean ::make(static::class) factory style as browse actions.
  • Default filter factories now accept optional alias, label and icon overrides.
  • setBrowseFilters() now silently ignores null filters, so conditionally-available filters can be passed inline.
