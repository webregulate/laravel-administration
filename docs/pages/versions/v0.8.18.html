Introduces fully Livewire-driven manageable model create/edit screens, a Database Schema viewer and a Scheduler & Jobs page for developers. Also simplifies logo configuration: provide a single image and optionally let WRLA recolour it automatically for dark mode.

Breaking Changes

  • The logo config no longer uses the light and dark keys. It now uses a single src image plus optional per-mode styling. The old light / dark keys still work for now, but they are deprecated — please move to the new format.

Features

Manageable Model Upsert

  • The manageable model upsert page is now handled entirely by the ManageableModelUpsert Livewire component. Creating and editing records is driven by a single save() method that runs validation, persists the model and logs the change — no more separate controller POST route.
  • Saving happens in place without a full page reload, and an inline success message confirms the record was saved. This keeps you on the same screen with your scroll position and form state intact, which is much nicer when making a series of quick edits.
  • Fields bind directly to Livewire, so complex inputs (such as SearchSelect, croppable and standard image uploads, and the WYSIWYG editor) stay in sync with the component's data and validate reactively.
  • Buttons now support loading states, giving clear visual feedback while a save is in progress.

Database Schema Viewer

Powered by albertoarena/laravel-truss, the viewer gives master/developer users a visual diagram of the application's database tables and relationships, either embedded inside the WRLA layout or opened as the standalone Truss dashboard.

  • New Database Schema page (wrla.database-schema) served by the DatabaseSchema Livewire component and shown in the navigation when enabled.
  • Configurable via a new database_schema_viewer config block: control who can access it, whether it renders embedded or via redirect, the default colour mode, which database connections are shown, and any extra Truss options.
  • Available as a Dev Tools shortcut, so developers can jump straight to the schema diagram.

Scheduler & Jobs

Master/developer users can inspect scheduled tasks, view and delete pending queue jobs, and retry, delete or flush failed jobs without touching the command line.

  • New Scheduler & Jobs page (wrla.scheduler) served by the Scheduler Livewire component and shown in the navigation when enabled.
  • Scheduled Tasks section lists every registered task with its type/flags (no overlap, one server), cron expression (human-readable) and next run time.
  • Pending Jobs section lists queued jobs (for the database queue driver) with the ability to delete an individual job.
  • Failed Jobs section lets you retry or delete a single job, or retry-all / flush-all in one click.
  • Ad-hoc task runs — a “play” button on each scheduled task lets authorised users run it on demand, gated by a new scheduler.can_run_adhoc config option.
  • Each section is collapsible, and the open/closed state is persisted per-user in the browser via Alpine's $persist.
  • Configurable via a new scheduler config block: control who can access it and the maximum number of pending/failed rows loaded at once.
  • Available as a Dev Tools shortcut, so developers can jump straight to the page.

Logo Configuration

  • Use one logo image for everywhere via src.
  • Optionally set a separate dark-mode logo with src_dark — leave it null to reuse the same image.
  • Add CSS classes per mode with light_classes and dark_classes. The default brightness-0 invert turns a dark logo white in dark mode automatically, so most projects only need a single image.

Upgrade Guide

Database Schema Viewer

1. Add the database_schema_viewer config default

In your published config/wr-laravel-administration.php, paste the new block after the logs section and before the THEME / STYLING CONFIGURATION divider: 

// Database schema viewer (albertoarena/laravel-truss) configuration
'database_schema_viewer' => [
    // Who may access the page: true / false, a Closure($wrlaUserData): bool,
    // or null to fall back to the developer check (WRLAHelper::userIsDev()).
    'enabled' => null,

    // 'embed' (Truss dashboard inside the WRLA layout) or 'redirect' (standalone Truss page).
    'display' => 'embed',

    // Default colour mode until the user toggles it: 'light', 'dark', or 'auto'.
    'default_mode' => 'dark',

    // Connections (keys from config/database.php) to visualise, with per-connection
    // Truss options. Leave empty to use the default connection.
    'connections' => [
        // 'mysql' => [],
    ],

    // Extra config passed straight through to Truss (config/truss.php).
    'truss' => [
        //
    ],
],

2. Register the route and nav item in WRLASettings.php

In app/WRLA/WRLASettings.php, import the component and add the route inside buildRoutes(): 

use WebRegulate\LaravelAdministration\Livewire\DatabaseSchema;

// ...inside buildRoutes()
// Database schema viewer - Enabled via `wr-laravel-administration.database_schema_viewer.enabled`
Route::get('database-schema', DatabaseSchema::class)
    ->name('wrla.database-schema');

Optional: Add the navigation item inside buildNavigation(): 

// Database Schema (albertoarena/laravel-truss)
NavigationItem::make('wrla.database-schema', [], 'Database Schema', 'fas fa-diagram-project')
    ->showOnCondition(fn() => WRLAHelper::databaseSchemaViewerEnabled()),

Scheduler & Jobs

1. Add the scheduler config default Required

In your published config/wr-laravel-administration.php, paste the new block after the logs section and before the THEME / STYLING CONFIGURATION divider: 

// Scheduler / Job manager page configuration
'scheduler' => [
    // Enabled, use either: bool, fn($wrlaUserData): bool, null (fallback using WRLAHelper::userIsDev())
    'enabled' => null,

    // Allow adhoc running, use either: bool, fn($wrlaUserData): bool, null (fallback using WRLAHelper::userIsDev())
    'can_run_adhoc' => null,

    // Maximum number of pending / failed job rows to load into the table at once.
    'max_rows' => 60,
],

2. Register the route in WRLASettings.php Optional

In app/WRLA/WRLASettings.php, import the component and add the route inside buildRoutes(): 

use WebRegulate\LaravelAdministration\Livewire\Scheduler;

// ...inside buildRoutes()
// Scheduler & Jobs - Access via `wr-laravel-administration.scheduler.enabled` configuration
Route::get('scheduler', Scheduler::class)
    ->name('wrla.scheduler');

3. Add the navigation item in WRLASettings.php Optional

Add the navigation item inside buildNavigation() so the page appears in the sidebar when the user is allowed to access it: 

// Scheduler & Jobs
NavigationItem::make(url: route('wrla.scheduler'), name: 'Scheduler & Jobs', icon: 'fa fa-clock-rotate-left')->showOnCondition(fn() =>
    WRLAHelper::schedulerEnabled()
),

Logo Configuration

Publish the new default logo asset Required

If you don't already have your own logo set, run the following to publish the new default logo image (vendor/wr-laravel-administration/images/logo.svg) into your public directory: 

php artisan vendor:publish --tag=wrla-assets

Update the logo block Required

In your published config/wr-laravel-administration.php, replace the old logo block: 

// Old
'logo' => [
    'light' => 'vendor/wr-laravel-administration/images/logo-light.svg',
    'dark' => 'vendor/wr-laravel-administration/images/logo-dark.svg',
],

with the new format: 

// New
'logo' => [
    // Logo src
    'src' => 'vendor/wr-laravel-administration/images/logo.svg',

    // Optional separate dark-mode logo. Leave null to reuse 'src'.
    'src_dark' => null,

    // Optional extra classes per mode. The dark default renders the logo white.
    'light_classes' => '',
    'dark_classes' => 'brightness-0 invert',
],

If you were using a single logo that looks fine on both themes, just point src at it and you're done — the dark_classes default will handle dark mode. If you have a purpose-made dark logo, set it on src_dark and clear dark_classes.

Note: if you already had custom light / dark logo values set, make sure to carry those paths over to the new src / src_dark keys after copying in the new default config block — otherwise your custom logo will be replaced by the default.
