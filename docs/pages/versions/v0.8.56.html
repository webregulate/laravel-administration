Consolidates the Database Browser changes from v0.8.51, adding dedicated access, safety and presentation configuration alongside shared dynamic filter fixes and layout improvements.

Breaking Changes

  • Configuration update: Database Browser access, connection/table restrictions, write permissions, pagination, filtering, value previews and record forms are now controlled by the new database_browser block. Merge this block into your published config/wr-laravel-administration.php; database_schema_viewer remains separate and does not control the browser.
  • Browser-specific pagination and upsert settings take precedence over the general browse.pagination and upsert settings. The null defaults retain inheritance. Full-page saves still return to the table by default; page and modal save behavior now use the actual form being rendered.
  • MySQL and MariaDB record URLs can no longer target a database other than the connection's configured database. Define a separate allowed Laravel connection for each additional database you need to browse.

Configuration Migration

Add the following block alongside database_schema_viewer. Preserve your application's existing configuration rather than force-republishing the entire file. These defaults retain developer-only access and existing write permissions; choose allowed connections, exclusions and read-only settings explicitly when restricting access to sensitive or production data. 

'database_browser' => [
    'enabled' => null,
    'connections' => null,
    'default_connection' => null,
    'excluded_tables' => [
        '*' => [],
    ],
    'read_only' => false,
    'read_only_connections' => [],
    'permissions' => [
        'create' => true,
        'edit' => true,
        'delete' => true,
    ],
    'pagination' => [
        'default' => null,
        'perPage' => null,
        'max_per_page' => 1000,
    ],
    'filters' => [
        'enable_all_fields' => true,
        'max_filters' => 50,
        'max_value_length' => 10000,
    ],
    'display' => [
        'value_max_length' => 300,
        'tooltip_max_length' => 1000,
    ],
    'upsert' => [
        'mode' => null,
        'page' => [
            'return_to_browse_after_save' => true,
        ],
        'modal' => [
            'size' => null,
            'return_to_browse_after_save' => null,
        ],
    ],
],

enabled accepts a boolean, a WRLA-user-data callback, or null to inherit developer.enable. connections accepts a list of Laravel connection names; null allows all configured connections and [] allows none. Table exclusions support bare or schema-qualified wildcard patterns under * and individual connection names. Each write permission accepts a boolean or WRLA-user-data callback, but cannot override read-only mode or connection/table restrictions. See the Configuration page for every setting and a restricted-access example.

New Features

  • Added a Database Browser to Developer Tools. Access defaults to WRLAHelper::userIsDev() and can be overridden with database_browser.enabled. Access is checked on every Livewire request.
  • Browse reachable allowed connections, search table names, and view records with sortable columns, configurable pagination, and dynamic filters. Unavailable connections are reported without blocking the browser; MySQL and MariaDB table lists and record routes are scoped to the configured database.
  • Added an opt-in all-column filter, enabled by default in the Database Browser. Positive searches match any column; negative searches require every column to pass. Commas combine terms with AND, and pipes combine alternatives with OR, including terms across different columns.
  • Added ManageableModelDynamic to infer browse columns, form fields, and schema-based validation from the selected table, including numeric, date, boolean, enum, and JSON fields.
  • Tables with a single-column primary key support viewing, creating, editing, and confirmed permanent deletion, including string keys. Tables without a primary key or with a composite primary key remain browse-only.
  • Record forms provide separate NULL and database-default controls, with generated, auto-increment, and binary fields read-only. Existing primary keys cannot be edited.
  • Record actions follow database_browser.upsert, inheriting general upsert settings by default, with configured modal size, close-after-save behavior, loading feedback, and automatic table refresh after modal saves. Full-page routes remain available, including record links opened in a new tab.
  • Added connection allowlists, wildcard table exclusions, global and per-connection read-only modes, and independent create/edit/delete permissions. Restrictions also apply to direct URLs, modal actions, saves and deletes; unauthorized controls are hidden.
  • Added browser-specific page sizes with a maximum row cap, all-column-search control, filter count/value-length limits, cell-preview/tooltip lengths, and configurable page/modal return-after-save behavior.

Database Browser operations write directly to the database: they bypass application model hooks, casts, soft deletes, and business validation. Schema-based validation and database constraints still apply, and deletions are permanent.

Changes & Improvements

  • Shared dynamic browse filters now accept supplied schema columns and initial filters, with optional all-column filtering disabled by default for existing manageable models.
  • Filter additions and removals now immediately update browse results, and numeric zero is no longer skipped as an empty filter value.
  • Numeric comparison filters now use the connection's query grammar to quote column names instead of hard-coded MySQL quoting.
  • Improved filter accessibility with unique input IDs, accessible labels, and remove-button tooltips, plus wrapping layouts for narrower screens.
  • Reduced admin content padding to give wide tables more usable space.
  • Page forms can now remain open after saving without inserting a duplicate record on the next save.
  • Expanded focused Database Browser regression coverage using disposable in-memory SQLite databases, including access restrictions, revoked write permissions, pagination/filter limits, modal behavior and cross-database URL rejection.
