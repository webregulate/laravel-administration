Adds a per-template type (Markdown or HTML) to email templates, so each template decides how its body is rendered instead of relying on a single global config value.

Breaking Changes

  • This release ships a new migration that adds a type column to the wrla_email_templates table. After updating you must run php artisan migrate. The migration backfills all existing templates to markdown, preserving their current rendering behaviour.

Features

  • Email templates now have a type field (markdown or html, defaulting to markdown), selectable from a dropdown in the template editor.
  • Sending an email now uses each template's own type to decide how the body is built, falling back to the global email_templates.render_mode config for inline templates created via EmailTemplate::make().

Bug Fixes

  • Markdown email bodies now allow all markdown syntax (including inline HTML) through to the rendered email, instead of stripping it during conversion.
