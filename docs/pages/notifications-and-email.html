Notifications & Email

Use notifications for the admin panel and email templates for messages sent through Laravel mail.

Create an in-app notification

php artisan wrla:notification ReportReady

Edit the generated class in app/WRLA/NotificationDefinitions/, then call it from your application:

use App\WRLA\NotificationDefinitions\ReportReady;

ReportReady::make($user->id, [
    'message' => 'Your monthly report is ready.',
]);

Pass a user ID for a personal notification, or a user_groups key for a shared notification. WRLA stores one row per call, not one per group member. A group notification shares its read state. For individual read states, create one notification per recipient.

Choose what the dashboard shows

The default dashboard shows personal notifications and the shared admin feed. The widget starts on Outstanding (unread); switch to Completed or All to see read items. To show only personal notifications, set this in config/wrla.php:

// Under 'dashboard' => 'notifications'
'user_groups' => ['@self'],

Add group keys to show their shared feeds. This list controls what the dashboard queries, not group membership. Define group callbacks returning collections of users in WRLASettings::runtime() if your notification needs to resolve recipients, for example to email a group.

Customize a notification

MethodWhat to customize
mount()Initialize the definition from the data saved with the notification.
getTitle(), getMessage()The title and body shown in the panel.
getLink()An optional URL for the notification.
getButtons()Keep the default Read/Undo button or add a link or Livewire action.
getEmailMessage()A separate email body. Defaults to the panel message.
postCreated()Run follow-up logic after the row is saved. Email is not sent unless the definition asks for it.

Scaffold an email hook and a URL button when generating a definition:

php artisan wrla:notification InvoiceReady --email --buttons --button-type=url

Use --button-type=livewire for a button that calls a definition method. Authorize the operation in the handler; displaying a button is not an authorization check.

Send an email template

In Email Templates, create a template with category transactional and alias report-ready. Add the user.name mapping. The built-in editor hides the outer braces in the Mappings field; the full JSON is:

{
    "user": {
        "name": null
    }
}

Use {{ user.name }} in the subject or body. Pass a model or keyed array when sending. WRLA only pulls the mapped attributes from a model. A string in place of null supplies a fallback for an empty value.

use WebRegulate\LaravelAdministration\Models\EmailTemplate;

$template = EmailTemplate::getByCategoryAlias('transactional', 'report-ready', [
    'user' => $user,
]);

$sent = $template->sendEmail($user->email);

Use getByAlias() if your aliases are unique across categories. Both lookups throw if the template is missing. For a message you don't need to save, use EmailTemplate::make('Report ready', 'Your report is ready.').

If a template has no type, WRLA uses email_templates.render_mode from config/wrla.php. The editor previews the subject and body with placeholder values. Save changes before using Send Test; it sends real email to the addresses you enter.

$subject = $template->getFinalSubject();
$body = $template->renderEmail(); // Render only; does not send.

Delivery options

$sent = $template
    ->replyTo('support@example.com')
    ->sendEmail(
        $user->email,
        attachments: [$reportPath],
        smtpKey: 'smtp',
    );
  • Recipients can be a single address, an array, or a comma-separated string. WRLA sends separate messages by default with the same template data. For per-recipient data, send separately after setting that recipient's mappings.
  • With sendSeperateEmails: false (the parameter is spelled this way), the first address is To and the rest are CC. Recipients can see those CC addresses.
  • attachments takes application-controlled file paths. Set smtpKey to an SMTP mailer in config/mail.php. WRLA writes send details to the smtp log channel, including mappings and addresses; avoid passing secrets as mappings.
  • Use setPostSendHook() on a template or setPostSendHookGlobal() for all templates. Each hook receives the template, addresses, attachments, and mailer key after a successful send.
  • Check the bool result. A batch may partly succeed before reporting failure. Mailer exceptions can still propagate, and success does not guarantee inbox delivery.
