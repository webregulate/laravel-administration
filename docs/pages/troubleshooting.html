Troubleshooting

Run Artisan from the Laravel application root, not the package checkout. Check the first failing step before changing configuration.

Admin route missing or access denied

php artisan route:list --name=wrla
php artisan migrate:status
php artisan wrla:edit-user
  • Check base_url in config/wrla.php. The default is /wr-admin.
  • Run pending migrations against the intended database. Check that the signed-in user has WRLA user data and the admin flag. Master and admin are separate flags.
  • If you disabled WRLA authentication routes, sign in through your app first. WRLA returns a 404 on denied admin requests in this mode.
  • For one model or tool only, check Model Permissions or the access rules in Admin Tools.
  • If Scheduler returns a 404 after sign-in, check scheduler.enabled in WRLASettings::runtime(). When it is null, Scheduler inherits developer.enable, which the installer can set more narrowly than “all masters.”

Assets, uploads, or overrides not showing

php artisan vendor:publish --tag=wrla-assets
php artisan storage:link
php artisan view:clear

WRLA publishes its assets under public/vendor/wr-laravel-administration/. If published copies are stale, review local edits before republishing with --force. The storage link is for the standard public local disk; a private disk does not need to be exposed publicly. For a view override, confirm that its path matches the active theme.

Configuration or route changes not taking effect

php artisan config:clear
php artisan route:clear
php artisan view:clear

Keep closures in WRLASettings::runtime(), not in the cacheable config. For an older install, preview php artisan wrla:upgrade --dry-run and follow the 0.10.1 upgrade guide. Rebuild deployment caches after verifying changes.

Email or jobs not working

php artisan schedule:list
php artisan queue:failed
  • Email: Confirm the template category, alias, mappings, and configured SMTP mailer. Save the template before using Send Test. Check the SMTP logs under storage/logs/smtp/ and use a safe test inbox. See Notifications & Email.
  • Scheduled task not running: Check that Laravel lists it and your deployment invokes Laravel's scheduler. The WRLA page does not run scheduled tasks automatically.
  • Queued job not running: Check that a worker is consuming the right connection and queue. WRLA only lists pending jobs for the database queue driver and failed jobs for database-backed failure storage.
