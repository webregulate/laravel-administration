Authorization

Authorization decides who can enter WRLA and what they can do there.

Grant admin access

php artisan wrla:edit-user

Select the user and grant admin access. WRLA's wrla_is_admin middleware checks the signed-in user's WRLA user data with isAdmin().

  • Admin grants access to the panel.
  • Master is a separate flag. The generated settings use it for tools such as Developer Tools and File Manager. A master still needs the admin flag to enter WRLA.

Protect a custom page

Routes in WRLASettings::buildRoutes() already require admin access. Add a Laravel Gate when not every admin should see a page:

// Inside WRLASettings::buildRoutes(), using Illuminate\Support\Facades\Route
Route::view('reports', 'admin.reports')
    ->middleware('can:view-admin-reports')
    ->name('wrla.reports');

Define view-admin-reports in your application. Hiding a navigation link does not protect its route or its Livewire actions.

Account settings and impersonation

Manage Account opens the current user's edit form. The generated App\WRLA\User class defines which fields WRLA shows there.

The Users screen can also offer Login as, which switches the current session to another user's account. WRLA opens the admin dashboard if the target is an admin, or the frontend otherwise. The WRLA sidebar offers a switch-back link while impersonating. If your workflow includes frontend accounts, provide that link in the frontend too:

@if (session()->has('wrla_impersonating_user'))
    <a href="{{ route('wrla.impersonate.switch-back') }}">Switch back</a>
@endif

The generated User model disables its IMPERSONATE rule. Keep it disabled unless you have a server-side policy for both who can impersonate and which accounts they may access. A broad operator-only rule does not restrict the target account.

For access to a specific model, see Model Permissions.
