Model Permissions

Use ManageableModelPermissions to control access to a model's WRLA screens and actions. These rules are separate from access to the admin panel.

All model permissions

Enum caseWhat it controlsGenerated default
ENABLEDModel navigation, browse columns and row actions, and access to create/edit forms. Not a substitute for BROWSE.Admins only
BROWSEAccess to the model's browse page. Reordering also requires EDIT.true
CREATECreating records. The built-in import and duplicate buttons also check this rule.true
EDITEditing existing records. Reordering also requires BROWSE.true
DELETEDeleting records, including bulk deletion.true
RESTOREThe restore button and bulk restore for soft-deleted records.true
SHOW_IN_NAVSidebar visibility only. Turning this off does not block direct access.true

These are the defaults in the generated WRLASettings, not necessarily the rules in your application. Do not rely on a hidden button as a server-side access check. In particular, the single-record restore handler does not check RESTORE; enforce that restriction server-side if your application requires it.

Example: set all seven rules on one model

use WebRegulate\LaravelAdministration\Enums\ManageableModelPermissions as Permission;

// Inside mainSetup()
$mastersOnly = fn ($userData) => $userData?->isMaster() ?? false;

static::setPermission(Permission::ENABLED, true);
static::setPermission(Permission::BROWSE, true);
static::setPermission(Permission::CREATE, $mastersOnly);
static::setPermission(Permission::EDIT, $mastersOnly);
static::setPermission(Permission::DELETE, $mastersOnly);
static::setPermission(Permission::RESTORE, $mastersOnly);
static::setPermission(Permission::SHOW_IN_NAV, true);

Replace the generated permission lines in your model's mainSetup(). WRLA still requires users to be admins to enter the panel. A rule can be a boolean or a callback that receives the current user's WRLA user data, or null.

Set a default for all models

In WRLASettings::runtime(), edit the existing default_manageable_model_permissions array:

// Uses the Permission alias from the first example.
Permission::DELETE->value => false,

A model's explicit rule wins. The generator adds explicit rules, so remove any that should inherit your defaults. For custom actions, enforce your access rule in the server-side handler as well as in the UI.
